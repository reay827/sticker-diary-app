# 하루 조각 · Sticker Diary

직접 찍은 사진을 스티커로 모으고, 글과 함께 하루를 기록하는 Android 시제품입니다.

**[첫 테스트 APK 다운로드](https://github.com/reay827/sticker-diary-app/releases/tag/v0.1.0-alpha.1)** · [폰 테스트 순서](docs/PHONE_TEST.md)

**[PC 가상폰 테스트](docs/PC_TEST.md)**: 이 개발 PC에는 가상폰 시스템·x64 APK·실행 버튼을 준비했고 가상폰 부팅과 앱 첫 화면 표시를 확인했습니다. `PC테스트-시작.cmd`로 실행하고 `PC테스트-사진추가.cmd`로 테스트 사진을 넣습니다. 배경 제거 품질과 호환성은 추가 확인이 필요합니다.

## 구현한 흐름
- 앨범 선택·카메라 촬영 → 기기 내부 자동 배경 제거 → 이름·촬영 날짜 입력 → 저장.
- 넓게 펼쳐진 스티커 보드: 자동 배치, 이동, 확대·축소, 상세 보기.
- 확대 이미지 아래 이름·촬영 날짜 표시, 정보 수정, 보관함 삭제.
- 날짜별 여러 일기, 한글 본문, 스티커 재사용·이동·크기·회전·삭제.
- 기기 내부 파일 저장, 재시작 복원, 이전 저장본 복구, 미저장 이탈 확인.
- 스티커함 삭제 후 기존 일기에서 사용한 이미지 유지.

## 실행
Flutter **3.47.8**, Java 17, Android SDK 36, Android 7.0(API 24) 이상을 사용합니다.

```sh
flutter pub get --enforce-lockfile
flutter analyze
flutter test
flutter run
flutter build apk --debug --target-platform android-arm64
```

GitHub Actions의 **Android APK** 작업에서도 검사 후 테스트 APK를 만듭니다. 실행 결과의 `haru-jogak-android` 아티팩트에서 내려받을 수 있습니다. APK에는 사진이나 개인 기록을 포함하지 않습니다.

개발 전용 테스트 서명은 Git에 올리지 않고 개발 PC의 `tools/prototype.p12`로만 보관합니다. 해당 PC에서 만든 APK는 업데이트 시 서명을 유지합니다. CI에서는 임시 서명으로 빌드 가능 여부를 검증하므로 실행마다 CI APK의 서명이 달라질 수 있습니다. 기기 내 기록을 유지하는 업데이트에는 같은 PC에서 만든 APK를 사용하세요. 스토어 출시에는 별도 비공개 서명과 별도 앱 ID를 사용해야 합니다.

## 사진과 개인정보
배경 제거는 Google ML Kit Subject Segmentation(Android 베타)으로 기기 안에서 실행합니다. 최초 사용 시 Google Play 서비스가 모델을 내려받아야 하므로 인터넷 연결이 필요합니다. 사진을 자체 서버에 업로드하지 않습니다.

자동 결과를 확인한 뒤 저장하세요. 실패하면 다른 사진으로 재시도하거나 **사진 그대로 사용**을 선택할 수 있습니다. 이 경우 배경이 포함된 사진으로 저장되며 자동 오려내기 성공으로 취급하지 않습니다. 정밀 보정·사각형 자르기는 아직 없습니다.

사진에 촬영 정보가 없으면 날짜를 직접 선택합니다. 등록 날짜를 촬영 날짜로 대신 채우지 않습니다. 방금 촬영한 사진에 한해 오늘 날짜를 제안합니다.

기록은 앱 내부에 저장하며 앱 자동 백업은 비활성화했습니다. 자체 백업·내보내기는 아직 없습니다. 앱 삭제·기기 분실 시 기록을 잃을 수 있으므로 중요한 기록의 장기 보관은 후속 백업 기능을 기다려 주세요.

## 검증 범위와 남은 작업
저장·복원, 한글·줄바꿈, 독립 스티커 이동·크기·회전, 투명도, 삭제 참조, 저장 실패·손상 복구와 주요 화면 흐름 자동 검사 12개를 통과했습니다. Windows에서 Android APK 빌드와 서명 검증을 완료했습니다.

실제 Galaxy 기기의 카메라·사진 선택, 모델 다운로드, 배경 제거 품질·메모리, 터치 조작은 추가 검증이 필요합니다. 빌드 성공은 실기기 검증을 대신하지 않습니다. 보드는 유한 영역이 확장되는 방식이며 검색·분류·수동 정렬과 iPhone 지원은 후속입니다.
